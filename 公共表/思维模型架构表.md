# 逻辑任务组
- 空间逻辑
  在使用复选框的时候，我突然遇到了一个需求：单个单个的复选框勾选的话obsidian的复选框功能已经能够支持了。

  **但是obsidian并不原生支持表示多个复选框之间的关系**

  对于那些复杂的任务来说，任务之间是有层级关系的，例如你定义了考研课程听讲的一轮：看完英语一、政治一、数学一、408。但是呢往往你在学校的时候一天没有时间全部完成。这时候我们希望定义的一轮是其中之一即可

  这时候引入了一个概念：OR逻辑，或者在形式上讲，我们有两个层级的复选框：
   - [ ] 一轮
   - [ ] 具体的课程
  在编程语言中，这种有多种可能性但是呢只选择其中一种特定情况的类型，叫作枚举enum

```rust
enum 今天的考研课程{
	英语一,
	数学一,
	政治,
	408综合,
}
```

  这对我们描述复选框之间的关系很有帮助。具体的课程完成了其中一个复选框，那么今天一轮这个抽象层次就已经完成了，其他枚举变体的课程的复选框就不可选择。当然往往用户只关注几个复选框是否为一组，他们可能并没有想到统一高层抽象这种东西，自然也不会更加繁琐的增加一个高层复选框，并且命名。但这种东西在逻辑和代码中是要有的。只是对于用户需要隐藏

  对于这种多对一的关系模型，还有另一种关系：AND
  即多个子复选框必须同时勾选后，主复选框才能自动被勾选

  这是一个和的逻辑，那么在编程中也有类似的模型，这个类型被称作结构体struct

```rust
struct 应用统计学备考{
	x: 听课, //x是个命名，听课是个类型
	y: 作业,
	z: 考卷自测,
	w: 真实现场考试,
}
```

  在这个例子中，x，y，z，w任务是必须的，实现了这些子任务后，上层抽象应用统计学备考才能完成

  当然为了简化用户使用，他们不关心命名，编程中通常会给出一些不关心字段命名的写法，例如具名元组

```rust
struct 应用统计学备考(听课, 作业,考卷自测, 真实现场考试);  
```

  这里只有类型，但是没有命令，写的时候是爽了，但是没有字段名，其实不是很好定义每个字段的具体任务是什么。当然rust中有解构语法，这里不展开

- 时间逻辑

  时间也是如此，你不可能一天完所有任务，必须拆分到不同时间完成，但是呢一般来说，我们不需要or逻辑，只需要and逻辑。但是注意deadline的问题，往往太严格的and逻辑容易无法执行，所以一般都是对区间进行操作，具体的交给每天空间逻辑去管。对于越过deadline无法完成的情况呢是需要进行错误处理的。在你有大量的时间的时候错误处理的时间容错空间很大，但是如果你的各个区间之间挨得很紧的话。这在一个长目标，大规划拆分为连续的小目标的场景中特别常见。

  面临一个错误处理和下一段任务区间的并发竞争问题，我们不可能把大段的错误处理全部合并到下一段任务区间的开头，这会导致下一任务区间的开头无法完成从而和后面的任务并发循环阻塞

  两种思路：一种是拆分错误处理为多个小段，在下一个任务区间每天的睡前末尾处理这一小段。这样在并发的运行范围内。另一种华而不实：就是单线程模型，阻塞下一段任务区间直到错误处理完成。
